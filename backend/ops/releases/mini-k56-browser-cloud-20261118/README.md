# Mini K56 CBT browser journal

This release adds a Mini-specific browser grant and Collector endpoint. It reuses the existing owner resolver, signed ticket format, immutable browser batches, and destination bindings. The separate enrollment table records only a pilot ID, opaque scope hash, and renewal limit. A grant verifies the original Mini CBT session, generation, class, and learner before enrollment. When new grants stop, an enrolled session can renew a ticket for its sealed batch within the original time limit. Paper uses Collector.

The browser batch selector routes technical events within the Worker byte limit. Content remains on the Collector path, with the original order and sealed destination preserved. The cloud writer receives the existing technical projection. Check leaf manifests and private log handling before any release.

Run `stage.py <captured-app.js> <new-overlay-directory> <captured-app-sha256>` to generate the API overlay. Deploy `connect.mjs` and `mount.mjs` as siblings under `src/mini-k56-browser-cloud`. Check the running source hash, apply `enrollment.sql` in the K56 database, and mount the Mini browser policy and existing ingress append key through `K56_MINI_CBT_BROWSER_POLICY_FILE` and `K56_MINI_CBT_BROWSER_APPEND_KEY_FILE`. Use a policy with `enabled`, `opensAt`, `closesAt`, and `renewUntil`. Times are integer UTC epoch milliseconds. Stop new grants through `enabled: false` and keep the endpoint available for existing sealed batches.

The isolated test uses the existing roster-backed native Mini fixture. Set its variables as documented in the sibling native cloud release. Also set `MINI_BROWSER_WORKER_ROOT` to the isolated Worker source directory. To exercise actual browser IndexedDB, set `MINI_BROWSER_PAGES_JOURNAL` to the Pages candidate `term-tests/shared/exam-journal` directory and `MINI_BROWSER_PLAYWRIGHT_PACKAGE` to the local Playwright package anchor. Run `node --test backend/ops/releases/mini-k56-browser-cloud-20261118/browser-grant.test.mjs`.

The test performs a native roster prepare, obtains a grant from the actual Express handler, verifies Worker admission and signed archive scope/ID/hash, and checks incorrect scope, expired tickets, paper, superseded sessions, and renewal during drain. The browser case keeps a batch through a lost ACK and reload, replays the same payload, and reads the separate content back from encrypted fixture storage. The publisher is isolated. This evidence does not cover live Worker/Pub/Sub/R2/GCS or a production learner submission.
